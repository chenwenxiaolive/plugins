# Internal GitLab

- The endpoint is `https://gitlab.iquest-inner.com/`; use HTTPS for remotes, `glab` and raw requests, with certificate checks on. `gitlab-cn-beijing.siflow.cn` in old docs, scripts or locks is historical; for a dependency still pinned there, use its per-command URL override (such as `MEGATRON_REPO_URL`) rather than editing pins.
- Authentication is already configured here (environment variables and Git settings) and on the nodes and gates (`/volume/.bashrc`, `/volume/.config`); there is no login step. `glab auth status` showing no login means nothing; test with a read-only request (`git ls-remote <url>` or `glab api projects/:id`).
- Run `glab` in the checkout so it infers the project: `glab issue view <iid>`, `glab mr list`, `glab api --paginate 'projects/:id/issues/<iid>/notes?sort=asc&per_page=100'` (without paging you get only the newest 20 notes). `glab api` has no `--jq`; pipe it to `jq`. `-R <group>/<project>` targets another repository.
- From this machine, GitLab goes through `sh-gate`'s proxy over the local tunnel `gate-proxy-tunnel.service` (`127.0.0.1:18080`); `glab` and Git already use it. For raw requests: `curl --proxy http://127.0.0.1:18080 --noproxy '' https://gitlab.iquest-inner.com/...`. Nodes and gates use their own network; don't copy this proxy to them.
- If access fails: check `systemctl status gate-proxy-tunnel.service`, then repeat the read-only request, then report the host, operation and sanitized error. Proxy and tunnel changes need an explicit ops request.
- A closing keyword (`closes`, `fixes`, `resolves`) before an issue reference in a commit merged to the default branch closes that issue; for one item of a tracking issue write `#<N> item <X>`.
- OSS credentials for jobs: `source /volume/.config/oss/<account>.env` in `run.sh` (`qr` for bucket skyinfer-qr, `zg` for skyinfer-zg); each file sets `OSS_ACCESS_KEY_ID`, `OSS_ACCESS_KEY_SECRET`, `OSS_ENDPOINT` and `OSS_REGION`. The control machine's copy is the source, deployed with `profile.sh push <gate>` (gate.md).
