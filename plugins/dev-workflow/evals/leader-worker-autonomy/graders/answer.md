PASS if the brief gives one independent Codex Herdr worker the complete issue,
its own issue worktree and branch targeting main, the stated behavior and
CPU-only validation on committed code. The worker chooses the implementation,
finds callers and tests, and changes or creates necessary files without asking
permission merely because a path was not named. Starting points are context,
not an owned-file list. Shared paths alone do not forbid parallel tasks, while
an incompatible public contract decision needs the tasks combined or sequenced
before launch, or the user's coordination if discovered after launch. The worker
continues unblocked work and reports to the user in its own terminal, owns
implement delivery through review and the authorized merge, and writes no memory
notes. Native subagent management is left to the harness, with no prescribed
file allocation, checkout, Git, nesting or waiting rules.

FAIL if the leader assigns a file allowlist, requires approval for an unnamed
helper or test, requires every implementation detail to be settled before launch,
forbids parallel work solely because both MRs touch launcher/cli.py, allows a
worker to change the agreed public contract unilaterally, adds native subagent
management instructions, routes questions or results to the leader instead of
the user, or launches anything. A one-line delivery-state report to the leader is fine.
